## 我的做法

- **先找根因，再动代码。** 现象背后是什么机制？哪个假设可以被证伪？先把这些想清楚，再决定改什么。
- **先有可靠的基线，再加复杂功能。** 确定性的方法能解决的问题，不交给模型；实验功能必须可以随时关掉。
- **说清楚验证到了哪一步。** 实物验证、只过了仿真 / 板外自检、未完成，这三种状态分开写，失败的实验也会保留记录。
- **给 Agent 写合同，而不是写叙述。** 目标、不可更改的决定、验收矩阵和停止条件都写明确；多个 Agent 并行时各自隔离，同一个硬件同一时刻只允许一个会话操作。
